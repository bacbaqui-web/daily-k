# ㅋㅋㅋ

ㅋㅋㅋ는 애객 고유 댓글의 literal ㅋ 합계 10개 이상인 글 중 검증된 게시 시각부터 최근 24시간인 유머를 모읍니다. 날짜·오전/오후 메뉴 없이 만 24시간에 활성 목록에서 내려갑니다. ㄴㅇㅅ 뉴스는 한국시간 09:00/21:00에 조사·검증 후 한 번에 발행하고, 최근 실제 발행 회차와 날짜별 기록을 보여 줍니다.

**현재 우선 계약:** [24시간 유머](ops/rolling-humor.md), [뉴스 단일 조사·발행](ops/news-single-run.md). `scripts/humor/collector.py`는 AI 없는 일반 프로그램으로 개발·오프라인 검증됐지만 상시 클라우드 실행환경은 아직 연결되지 않았습니다. 기존 AI 감독형 수집기를 재가동하거나 일반 매크로라고 부르지 않습니다. 아래 회차형 유머/11개/사이트 최초 공개 후 24시간 설명은 과거 운영 기록이며 새 유머 경로에는 적용하지 않습니다.

기존 [진행 중·확정 계약](ops/live-records.md)과 [JSON Schema](schemas/live-input.schema.json)는 과거 운영 기록입니다. 새 뉴스 입력은 [단일 발행 스키마](schemas/news-publication.schema.json)를 사용합니다. 기존 회차·공유 링크·본문 이미지·영상·뉴스 이슈 기록은 보존합니다. 아래 과거 24시간 만료와 08:55 발행 설명은 기존 구조의 기록이며 새 창/불변 확정본에는 적용하지 않습니다.

이 저장소는 `code/02_tools/daily_k/홈페이지`에서 관리합니다.

- 사이트: https://bacbaqui-web.github.io/daily-k/
- ㅋㅋㅋ: 오전 9시·오후 9시 커뮤니티 화제·유머·정보 브리핑
- ㄴㅇㅅ: 오전 9시·저녁 9시 한국어 뉴스 브리핑, 날짜·회차별 영구 보관
- 커뮤니티 목록은 대표 이미지 한 장, 읽기 창은 확인한 본문 이미지 전체를 원문 순서대로 표시(외부 URL 연결·지연 로딩·실패 시 원문 안내)
- 우리 사이트 최초 공개(`firstPublishedAt`) 후 24시간 자동 만료, 읽음 처리, 영상 미리보기 및 키보드 탐색

## 빌드 및 배포

`npm ci` 후 `npm run build`를 실행합니다. `python3 scripts/prepare-pages.py`로 경로를 정리한 뒤 main에 반영합니다. GitHub Pages는 main의 /docs에서 배포합니다.

커뮤니티 브리핑은 [운영 지침](ops/community-briefing.md)에 따라 Codex 예약 작업이 웹을 확인해 선별·발행합니다. 기존 Python/WebKit 수집기와 LaunchAgent는 중지했습니다. 과거 수집 데이터와 앱 소스는 보존합니다. ㅇㅎㅂ 수집은 중지했고 해당 분류 필터와 배지도 제거했습니다. 기존 발행 글과 원문 제목은 보존하며 전체 목록에서 볼 수 있습니다. 새 회차는 댓글 ㅋ 합계 11개 이상인 유머를 우선 선정하고 문화·정보·뉴스성 화제 등을 보완하며 날짜별로 보관합니다. 이전 기준으로 발행한 ㅋ 10개 글은 유지합니다.

## 뉴스 운영

ㄴㅇㅅ 목록은 기존 게시글과 같은 형태로 제목과 두 줄 요약을 보여 줍니다. 항목을 누르면 전체 요약·강조 문구·관련 기사 카드가 읽기 창에 표시됩니다. 화살표 버튼과 키보드 좌우로 이동하고, 위아래 키로 스크롤하며, 바깥 클릭·Esc·모바일 제목 아래로 끌기로 닫습니다. 마지막 기사에서 다음 글을 누르면 창이 닫힙니다. 뉴스 순서는 브리핑의 중요도 순서를 유지합니다.

뉴스 자동화는 이 저장소의 [운영 지침](ops/news-briefing.md)을 읽어 검증한 기사를 발행합니다. 후보·초안은 `~/Library/Application Support/DailyK/news/`에, 공개 회차는 `public/data/news/`와 `docs/data/news/`에 저장합니다.

사용자가 제공한 2026-09-15~2026-10-02 오전 ChatGPT 뉴스 **35회차·291개**도 같은 목록에서 조회합니다. 같은 날짜·시간의 뉴스는 하나로 합치고, 겹친 이슈는 카드 안에 원래 기록을 함께 보관합니다. 원본 JSON과 출처 상태는 그대로 유지합니다. 132개 이슈로 분류하고 앞선 같은 이슈 기록으로 연결했습니다. 기사 URL·정확한 시각이 없는 자료를 검증된 뉴스로 표시하지 않습니다. [분석·보존 범위](ops/news-archive-analysis.md)를 참고하세요.

날짜 선택은 `← · 오전 · 날짜 · 오후 · →` 한 줄이며, 전체 요약의 핵심 문구를 굵게 표시합니다. 마우스로 뉴스에 잠시 머무르면 전체 설명과 관련 기사 카드를 스크롤하는 미리보기가 열립니다. 클릭 읽기와 모바일 동작도 유지합니다.

뉴스 읽기 창의 **공유하기**는 현재 선택한 뉴스가 바로 열리는 이 사이트의 링크를 복사합니다. **질문하기**는 해당 뉴스 설명·날짜·출처·함께 보관한 기록을 질문용 텍스트로 복사합니다. 복사한 내용을 ChatGPT에 붙여넣고 마지막 `내 질문:`에 질문을 적습니다. 연결된 이전 회차는 제목과 링크만 포함하고 전문을 가져온 것처럼 표시하지 않습니다. 자동 복사가 실패하면 직접 선택할 수 있는 텍스트 상자를 제공합니다. 사이트에서 AI API를 호출하거나 질문을 자동 전송하지 않습니다.

새 브리핑의 뉴스별 상세 설명은 보통 4~6문단, 8~12문장으로 배경·변화·의미·불확실성을 다룹니다. 단순한 소식은 2~3문단으로 작성하며 분량을 억지로 늘리지 않습니다. 첫 문단은 목록의 두 줄 요약에도 쓰는 짧은 핵심 설명입니다.

2026-10-02 오전 회차부터 뉴스에 공통 이슈 ID, 실제 사건 날짜·시간대, 진행 단계, 변화점과 정정 대상을 기록합니다. 발행할 때 `data/news/issues/index.json`과 이슈별 JSON을 함께 갱신하며, 관련 이슈는 7일 이전 기록까지 참고합니다. 원본 회차와 이슈 이력에는 자동 삭제 기한이 없습니다. 연표 화면은 추후 이 데이터로 구현할 수 있습니다.

이전 `~/Library/Application Support/DailyK/runtime/daily-k-github` 경로는 이 폴더로 연결되는 호환용 심볼릭 링크입니다. 실제 소스와 Git 이력은 이 폴더에만 있습니다.
