Daily K 뉴스 완성본을 작성해 주세요. 아래 기준은 이전 요청의 문체·분야별 수량·출력 형식보다 우선합니다.

선정
- 요청에 적힌 회차 ID와 한국시간 cutoffAt을 기준으로 실제 웹 검색을 하세요. 오전은 밤사이, 오후는 오전 이후 새로 확인된 내용을 우선합니다. cutoff 이후 보도를 섞지 마세요.
- 여러 언론사가 주요하게 다룬 공적 영향이 큰 뉴스를 중요도순으로 고르세요. 홍보성 발표보다 정치·경제·사회·안전 등 중요한 변화를 우선하세요. 기사 수·분야별 할당·웹툰·예비 기사 수를 억지로 채우지 마세요.
- 함께 제공된 이전 회차의 대표·추가·예비 기사와 비교해 새 사실 없는 반복은 제외하세요. 후속은 달라진 사실을 구체적으로 적으세요.

완성 문체
- 짧고 직접적인 제목, 본문은 기본 두 문장으로 작성하세요. summary 배열에 문장 하나씩 넣으세요. 각 문장은 핵심부터 자연스러운 존댓말로 쓰세요.
- 사실·핵심 수치·조건·주장 주체·전망과 확정의 차이를 지키세요. 불확실한 내용은 필요한 문장 안에서 짧게 밝히세요. 불필요한 해설·선정 과정·같은 뜻의 반복은 빼세요.
- 기사마다 핵심 수치·결정·결과 또는 중요한 미확인 사항 1~2곳을 emphasis 배열로 지정하세요. summary에 실제 있는 짧은 구절을 그대로 넣으세요. 문장 전체나 주어만 강조하지 마세요. 본문에 ** 같은 마크다운을 넣지 마세요.
- 예: title="엔비디아 매출, 1년 새 두 배로", summary=["엔비디아의 분기 매출이 지난해 같은 기간보다 103% 늘었습니다.","다음 분기에도 매출이 늘 것으로 전망했고, 발표 후 시간외 주가는 한때 3% 넘게 올랐습니다."], emphasis=["103% 늘었습니다","시간외 주가는 한때 3% 넘게"] (문체 예시이며 수치를 새 회차에 재사용하지 마세요.)

출처
- 각 기사에 실제 원문을 읽고 확인한 한국어 출처를 포함하세요. 보도일·시각과 사건 발생일을 구분하세요. URL·이미지 주소·시각을 추측하지 마세요.
- 출처는 name,title,url,publishedAt,imageUrl을 포함합니다. 원문 og:image 또는 twitter:image를 확인할 수 있으면 HTTPS 사진 주소를 넣고, 확인 못하면 imageUrl:null로 두세요. 검색 이미지나 무관한 사진으로 채우지 마세요.
- 확인 메모는 본문과 분리하세요. 사진 확인 불가와 기사 사실 확인 실패를 구분하세요. 사실 확인 실패한 기사는 제외하세요.

출력
- 설명이나 마크다운 본문을 중복 출력하지 말고 JSON 코드 블록 하나에 완성본을 주세요.
- 최상위: editionId,cutoffAt,intro,overview(짧은 2문장 배열),stories,events,keywords,omissionNotes.
- stories는 중요도순입니다. 각 항목: id(영문 숫자 하이픈),topicKey,category,title,summary,emphasis,status(확정/예정/검토/보도/주장/분석),publishedAt,eventAt,eventTimeNote,whatChanged,whyItMatters,uncertainty,keyFacts(핵심 사실 2개 이상의 문자열 객체),sources,relatedArticles(중복 없는 원문 1~3개),timeline(issueId,issueTitle,eventDate,eventEndDate,eventTimezone,stage,change),scoreComponents(importance,domesticImpact,reliability,recency,interest 각각 0~100),scoreReason.
- sources/relatedArticles 공통: name,title,url,language:"ko",kind:"news",publishedAt,imageUrl. 시각 미확인은 null로 두고 확인한 날짜를 publishedDate/publishedTimezone으로 별도 기록하세요. sourceCheck에 원문에서 확인한 사실과 접근 불가 여부를 적으세요.
- 후속이면 followUp:{editionId,storyId,delta}, 전날 기사면 fallbackNote에 새로 포함한 이유를 짧게 기록하세요. 이전 예비 기사 후속은 reserveUpdate에 이전 회차와 새 사실·sourceUrl·publishedAt을 적으세요.
- events는 확인된 일정만 {title,at,date,timeNote,detail,source}로, 없으면 []입니다. 기사 수나 일정 수를 채우지 마세요.
- 실제 검증 시각·해시·발행 operationId·승인 여부는 수신 측에서 기록합니다. 검증하지 않은 것을 검증했다고 쓰지 마세요.

표시·역할
- 웹페이지는 분야명 색, 짧은 제목, 간결한 본문, 선택한 강조 구절을 표시합니다. 기사 사진 왼쪽/출처·원문 제목·보도 시간 오른쪽 배치는 웹페이지가 처리합니다. 사건·발표 날짜 안내, '확인·관련 뉴스' 제목은 표시하지 않습니다. 데이터의 날짜는 검증용으로 보존합니다.
- 제목 클릭 창과 미리보기는 없습니다. HTML/CSS나 별도 화면을 만들지 마세요.
- Discord에는 중요도순 대표뉴스 제목 3개와 전체 뉴스 링크만 보냅니다. 전송은 수신 측이 합니다.
- 여기서 완성 문장을 작성합니다. 수신 측은 제목·summary·emphasis를 다시 쓰지 않고 검사·데이터 연결·게시만 합니다. 수정이 필요하면 이 대화에 돌려보냅니다.
- 예약을 만들거나 직접 게시·전송하지 마세요.
